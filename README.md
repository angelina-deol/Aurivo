# Aurivo

**AI-powered voice fraud & deepfake detection, built as a full-stack ML engineering project.**

Aurivo takes an audio clip and tells you whether it was likely generated by AI — with a real spectrogram, a confidence breakdown, and a plain-language explanation, not just a yes/no. It's built around [AASIST](https://github.com/clovaai/aasist), a published anti-spoofing model, wrapped in a production-style stack: FastAPI, Celery, Postgres, and a React frontend.

I built this to go deeper than a typical ML demo — the model is only maybe a third of the actual work here. The rest is what it takes to run inference reliably: async job processing, real audio preprocessing, storage abstraction, auth, and the kind of failure handling that only becomes obvious once you throw real files at a real worker process.

## What it does

- **Upload or record audio** (WAV/FLAC/MP3), get it analyzed for signs of AI generation
- **Real spectrogram** generated per clip, with the model's internal attention overlaid on it
- **Confidence + fraud score**, plus a natural-language explanation (Groq/LLM-generated, grounded only in the actual model output — no fabricated technical detail)
- **History & dashboard** — search, filter, and charts across all your past analyses
- **Google OAuth or email/password** login

## Architecture

```
┌──────────┐      ┌─────────┐      ┌───────────────┐
│  React   │─────▶│ FastAPI │─────▶│   PostgreSQL  │
│ frontend │      │ backend │      └───────────────┘
└──────────┘      └────┬────┘
                       │ enqueues
                       ▼
                 ┌───────────┐      ┌──────────────┐
                 │   Redis   │◀────▶│ Celery worker │
                 └───────────┘      │  (AASIST +    │
                                    │   torch)      │
                                    └──────────────┘
```

The web API and the ML worker are deliberately separate services — the API never imports `torch`, and a crash during inference can't take the API down with it (inference itself runs in an isolated subprocess, for the same reason).

## A few things worth knowing

- **The model's confidence tends toward extremes (0% or 100%)** rather than nuanced middle values — a known limitation of AASIST as a single-dataset (2019), raw-waveform model. Newer approaches that pair a pretrained speech model with an AASIST-style backend generalize better; swapping that in would be the natural next step if accuracy needed to improve.
- **Inference runs in an isolated subprocess**, not in the worker process directly — this came out of a real bug where a malformed MP3 crashed the native audio decoder outright (not a catchable exception), which took the whole worker down with it since it wasn't using Celery's default process pool. That's the kind of thing you only find by actually breaking it.
- **Test suite**: 50+ backend tests, including ones that deliberately trigger crash and timeout paths to prove the isolation actually works, not just that it looks right on paper.

## Future Development

- **Better generalization**: swap AASIST's raw-waveform frontend for a pretrained SSL encoder (wav2vec2/XLS-R) feeding into the same attention backend — the current model is confident but overconfident on anything outside its 2019 training data, and this is the well-documented fix for that.
- **Batch analysis**: analyze a folder of recordings in one job instead of one at a time.
- **Case management**: assign investigations to team members, add notes, track review status — useful once this moves from a solo tool to something a team uses.
- **Multi-model comparison**: run RawNet2/RawGAT-ST alongside AASIST and compare verdicts, rather than trusting a single model's output.
- **Real-time detection**: analyze a live call/stream instead of a completed recording.
